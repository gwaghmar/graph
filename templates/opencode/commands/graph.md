Execute `$ARGUMENTS` using Graph. Size first — F = files to change, D = design decisions, R = cross-cutting risk: F ≤ 1 with no D/R → one implementation node plus quality checks, no extra agents; F 2–4 or D = 1 → 2–3 nodes with at most one reviewer agent; F ≥ 5, D ≥ 2, or R → full planner/workers/reviewer protocol with one worker per independent file cluster. Initialize `.graph/graph.py init`, or use `.graph/graph.py resume` for `--resume`. Record all nodes and states, then run `.graph/graph.py validate` and fix the plan if it reports unknown or cyclic dependencies. Check the local cache before model calls. Run `.graph/graph.py quality` before reviewer agents. Retry only failures returned by `.graph/graph.py retry-plan --include-dependents`, maximum twice. Cache successful reusable nodes. Each `node` call prints a live ASCII graph of the run; do not re-describe progress in prose. Finish with `.graph/graph.py finish` — it prints the final run summary; include it verbatim in the reply along with the HTML report path. Commit only when explicitly requested with `--commit`.
